## Phase 4 — Study System Overhaul

### Step 13: Point system

Implement the card familiarity point system:

- Every card has a `points` field (integer, default `0`, stored in `user_card_progress` table — column already exists or add it)
- **Wrong answer**: `points += 2` (cap at 10)
- **Correct answer**: `points -= 1` (floor at 0)
- Points determine how often a card appears in study sessions via a **chance percentage**:
    - `chancePercent = points * 2` (so 0 points = 0%, 5 points = 10%, 10 points = 20%)
    - Cap at 20%
    - This means a card at 0 points still appears in normal rotation, it just doesn't get priority boosted
    - Cards with higher points have a higher probability of being shown more frequently
- **How it works in a study session**:
    1. Build the card queue for the session (all cards, or filtered by mode)
    2. Shuffle the queue
    3. As cards are served, use the chance % to occasionally re-insert high-point cards earlier in the remaining queue
    4. Specifically: after serving a card, roll a random number for each remaining card — if `Math.random() * 100 < card.chancePercent`, move that card closer to the front
    5. This creates a natural spaced repetition without rigid scheduling
- Points are updated in Dexie immediately, synced to Supabase via the existing sync queue
- A card at 0 points is considered "mastered" for stats purposes but still appears in sessions normally
- "Needs Review" = any card with points > 0
